# Signed answers: `asop.answer/1`

A person answers a human gate on their own machine. Their partition signs an envelope with a key
this hub's operator enrolled for them (`agentco human-key enrol`, [`agentco/humankeys.py`](../agentco/humankeys.py)).
Then a transport credential carries it to `POST /answers`. This is the hub-local **v1 contract** of
[ADR 0008](decisions/0008-control-loop-personal-and-company-hubs.md) §3 (Decision 1 = A). It is to be
proposed to asop-spec 0.7.0 as an additive change. Code: [`agentco/envelope.py`](../agentco/envelope.py).
It needs asop-spec 0.6.0 or later, for its canonical JSON.

## The payload

Every field is required, and an absent field is refused rather than defaulted.

| field | type | meaning |
|---|---|---|
| `type` | `"asop.answer/1"` | |
| `hub` | 32 hex | the hub's **generated** id (`GET /hub`, `hubId`), never its label |
| `item` | string | the ORIGINAL item the gate is on, never the vehicle (§8 S1) |
| `verify_attempt` | integer ≥ 0 | the item's `verify_failures` as read (§8 S1) |
| `stage` | integer ≥ 0 or null | the staged check answered; null for an unstaged gate |
| `epoch` | integer ≥ 0 | the run's ownership epoch; 0 for an item outside a run (§8 S2) |
| `verdict` | `{passed: bool, reason: string}` | |
| `choice` | string or null | |
| `signer` | string | the person, as declared in `ASOP_HUMANS` |
| `key_id` | string | the first 32 hex digits of the key's fingerprint |
| `nonce` | 32 lowercase hex | fresh for every envelope |
| `issued_at` | integer | Unix seconds |

Integers are never booleans, and duplicate keys and floats are refused at parse. For that reason
the envelope travels as **JSON text**: `{"envelope": "<the payload's JSON text>", "signature": "<base64>"}`.

## What is signed

The signed bytes are the type line, one `\n`, then the payload's canonical JSON as defined by the
spec (§3.10, `asop.manifest.canonical_json`).

- **Ed25519:** RFC 8032.
- **ECDSA P-256:** SHA-256, sent as the 64-byte `r || s`. `s` must be in the lower half of the
  group order; a high-S signature is refused.

The key fingerprint is the SHA-256 of the key's DER SubjectPublicKeyInfo:
`openssl pkey -pubin -in key.pem -outform DER | shasum -a 256`.

**Test vectors:** [`envelope-vectors.json`](envelope-vectors.json), generated by
`tools/envelope_vectors.py`. The keys in it are public test keys, so never enrol one.

- **Ed25519:** the vector pins the exact signature bytes.
- **ECDSA:** the vector pins one valid signature. A signer's own ECDSA output will differ and must
  still verify.

## What the hub checks, in order

Each check refuses before anything is written:

1. The carrier may reach the route. A transport-class credential carries only its own party's
   answers (`transport_party_mismatch`).
2. The schema (`envelope_invalid`).
3. The `hub` is this hub (`envelope_wrong_hub`).
4. The key is enrolled for the signer (`key_unknown`) and is not revoked **at arrival**
   (`key_revoked`).
5. The signature verifies (`signature_invalid`).
6. Age, measured at arrival from `issued_at`:
   - more than 300 s in the future: `envelope_future`;
   - up to `AGENTCO_ENVELOPE_FRESH_SECONDS` (default 24 h): applied;
   - within the grace window after that (`AGENTCO_ENVELOPE_GRACE_SECONDS`, default half of fresh):
     **held**. It is neither applied nor refused, and the response is 202. The owner confirms by
     signing a fresh envelope; that confirmation flow is the next build step.
   - older than fresh plus grace: `envelope_expired`.
7. The nonce. Resending the same envelope returns its stored outcome. A different payload under a
   used nonce is refused `replayed`.

After that come the queue's own rules:

- the signer is the gate's named human;
- `verify_attempt` is current, else `stale`;
- `epoch` is current, else `not_the_owner`;
- a second answer after a pass is refused `not_terminal`.

The stored attestation has `submitted_by` = the person and carries the envelope, signature, key,
nonce and carrier (`via`). The hub writes `check`, `exit_status`, `environment` and `at`, and none
of them is covered by the signature.

## Two stores, and what a retry does

The nonce row (registry database) is committed `received` before the attestation (work store) is
written. After the attestation lands, the row is set `applied` with its receipt.

- **Crash before the attestation:** the resend lands the answer.
- **Crash after the attestation:** the resend returns success and applies nothing twice. The
  attestation is keyed `envelope:<key_id>:<nonce>`, so the queue recognises it.
- **Two envelopes racing for one slot:** the loser's row is set `refused` and names the winner's
  `(key_id, nonce)`.

`GET /answers/{key_id}/{nonce}` returns a row's receipt, but only to the actor that carried it.
`envelope.prune` collects settled rows older than fresh plus grace. It never collects a `received`
row.

## The unsigned path (§8 B1)

Once a person has any key enrolled here, an unsigned `POST /work/{id}/attest` on a gate naming them
is refused `envelope_required`. The same holds over MCP. Revoking every key does not reopen it.
Until a person enrols, the unsigned path works as before, and its attestation carries no envelope,
which marks it as legacy.
